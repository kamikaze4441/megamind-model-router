## model-router
- At the start of every task, place it on a ladder: lookups and searches → Haiku · low; writing and day-to-day plans → Sonnet · medium; scoped edits → Sonnet · high; debugging → Fable · low; anything with money, security, data or live servers, and any change to code that handles them → Opus · high; reviews and fact-checks → Opus · high; research → Fable · low; architecture and long-term plans for a system or project → Fable · medium. When a test, a command or a lookup can check the result, start one step lower: scoped edits → Sonnet · medium; debugging → Opus · medium; research → Opus · medium. Security work stays on Opus (Fable 5.2 blocks most of it). Is it a small bug with all its code in the prompt? That is a scoped fix, not debugging: Sonnet · high, and run the code to check. Does the prompt name an effort? It wins: use the named effort on the start model of that kind of work. Risky work still never goes below Opus · high. Full ladders: `/model-router:route`.
- If this session's model or effort is below the task's step, or well above it on a lookup, writing or scoped-edit task, open the reply with one line, `⚙ Better on <model> · <effort>: <reason>`, then do the task. Say nothing when it fits. For risky work on Haiku or Sonnet, ask before acting.
- Hand bulk searching and reading to `model-router:scout`, test runs to `model-router:runner`, routine edits to `model-router:builder` and risky diffs to `model-router:reviewer`; any other Agent call names a model. Small steps stay with you. A prompt starting with `solo` turns this off; `orchestrate low` and `orchestrate high` set how much is delegated.
