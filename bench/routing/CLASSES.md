# Task classes (the router's labels)

Label each prompt with the ONE class whose description fits best. When two fit, prefer the earlier one in this priority order: risky, debug, plan, review, research, edit, write, search, quick.

- risky: an action or decision where a mistake costs money, security, privacy, data or uptime: deleting or migrating data, passwords/keys/auth/permissions/firewall/ports, changing a live server, container or network, payments, taxes, investing, legal or medical decisions, anything hard to undo.
- debug: something is broken or behaves unexpectedly and the cause is unknown: an error message, a failing test, a crash, wrong output, a slowdown, "why does X happen".
- plan: design or architecture with long-term consequences: structure a system or project, choose between approaches, write a roadmap, spec or decision record, set a strategy.
- review: evaluate existing work for errors: review code or a pull request, fact-check a document, check a plan or spec, proofread for correctness.
- research: gather and compare information from several sources to answer an open question or make a choice: product comparisons, "what is the best way to", the current state of something, buying decisions.
- edit: make a scoped change with a clear target: write or change a small function, script or config, add a feature in a few files, refactor, rename, change a setting in a file.
- write: produce or rewrite prose for a reader: emails, messages, posts, docs, summaries of given text, translations, explanations.
- search: find, locate, list or collect things inside given or reachable material (files, folders, logs, a long document, pages, an inbox); mostly reading and matching, little judgment.
- quick: a short question with a stable, known answer, or a one-step how-to, answerable in a few sentences without tools.
